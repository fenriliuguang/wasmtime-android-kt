### Fix — recycle canvas swapchain textures after GPU work (2026-08-27)

- Product `gpu-canvas-context.get-current-texture` was inserting a new Dawn `HandleTable` texture every frame. `queue.submit` / `context.present` presented but did not close that `GPUTexture`. Mali held BLAST images: hitching rose, then GpuThread SIGSEGV (`fault addr 0x20`) around 10s. Closing the image in the same `present()`, on the next acquire, or after a CPU-frame ring without a GPU fence UAFd Mali (`0x20` / `0x1f8`, crash delayed to ~45s). Dawn `queue.submit` registers `onSubmittedWorkDone` asynchronously and waits the **oldest** in-flight image only when more than **3** are live, then `tryDrop`s those whose GPU work is done. Do not block GpuThread on the current submit (that dropped vsync). Do not close the just-submitted `GPUCommandBuffer` or the on-screen swapchain image. Guest-owned textures are not swept. Cpu host keeps last + pending. Instrument `WasiWebGpuCanvasContextFrameLifetimeInstrumentedTest` (no GPU). Cloud has no device
