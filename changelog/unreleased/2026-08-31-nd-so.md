### Build — ND-SO Dawn C API Android `.so` recipe (2026-08-31)

- Recipe [`scripts/build-dawn-c-android.py`](../../scripts/build-dawn-c-android.py): CMake `DAWN_BUILD_MONOLITHIC_LIBRARY=SHARED` at Dawn SHA `9d41fdf36977cca92361c6ae2769129bbaaafd9b` (same as `androidx.webgpu:webgpu:1.0.0-alpha05` AAR `dawn_build_metadata.json`). Output `native/third_party/dawn-c/out/<abi>/libwebgpu_dawn.so` is gitignored. **Not** the product default (JNI leftover still default). **Do not** git-add `libwebgpu_c_bundled.so`.
- **Size:** androidx leftover `jni/arm64-v8a/libwebgpu_c_bundled.so` is **5.79 MiB** (6 073 392 bytes); x86_64 **6.31 MiB**. JNI-only (0 `wgpu*` C exports; 169 `Java_androidx_webgpu_*`). A second Dawn C `.so` in the default APK would add ~that order again — ND-DEFAULT **replaces** the bundled JNI `.so`, does not pack both. Self-built size is printed by `--build` when NDK is present (Cloud has no NDK; `--probe-aar` still records the leftover).
- **Android thread:** C API is in-process on the existing **GpuThread** / 8 MiB `wasmtime-cm-pump` (no extra ART thread, no `wasmtime-wasi` poller/event-loop threads). Dawn may still start its own Vulkan worker threads (same class as androidx native). Do **not** `AttachCurrentThread` on the pump. `webgpu.h` (`wgpuQueueOnSubmittedWorkDone`) is the C path for H8; the AAR `.so` only exports the JNI `GPUQueue.onSubmittedWorkDone`.
